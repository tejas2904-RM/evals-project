# EvalPilot — Phase 3: RAG bot as system under test (v1 → v2 → v3)

Phase 3 of `../Docs/Implementation-Plan.md`. Builds on Phase 2 (provider layer, cache, budget) and adds
the fund-house FAQ bot in three frozen versions, plus `evalpilot run` that writes immutable traces.

## Quick start

```bash
pip install -e ".[dev]"
copy .env.example .env
evalpilot run --provider offline          # 123 traces, $0
pytest
```

Paid run (once; reruns hit the cache). 123 `gpt-5.4-nano` calls, roughly $0.05:

```bash
evalpilot run --provider openai
evalpilot spend
```

## Versions

| Behaviour | v1 naive | v2 guardrails | v3 entity-aware |
|---|---|---|---|
| Retrieval | BM25 top-4, whole corpus | same as v1 | only the named fund's official docs; scraped docs never retrieved |
| Out-of-scope | answers | refused by scope gate before any model call | same as v2 |
| Fund recommendations | allowed | prompt forbids; output filter rewrites | same as v2 |
| "Guaranteed returns" | repeats scraped claims | prompt forbids; sentence stripped + disclaimer | same as v2, and scraped text never reaches the model |
| Citations | none required | prompt requires `[doc_id]`; non-retrieved ids dropped; sources appended if missing | same as v2 |
| Similarly named funds | confused | confused | resolved by longest alias match |

Guardrails are deterministic Python (`bot/guardrails.py`), so v2/v3 cost the same as v1. Detection
patterns live in `patterns.py` so the Phase 4 code graders can share them.

## Pipeline

```text
case ─► [v2,v3] scope gate ─refuse─► Trace(refused, no model call)
     └► retriever (v1/v2 BM25 · v3 entity-scoped) ─► prompt (V1/V2/V3) ─► LlmClient (cache, budget)
        ─► [v2,v3] advice filter ─► unsafe filter ─► citation fix ─► Trace
```

Each trace records `raw_answer`, the final `answer`, `retrieved_doc_ids`, `citations`, `refused`,
`guardrails` fired, `entities` detected, usage, cost and cache status. Runs go to
`runs/<run_id>/traces.jsonl` and `meta.json`.

## Offline fixtures

`data/offline_responses.jsonl` holds canned raw model output per `version:case_id`, generated by
`scripts/build_offline_fixtures.py`. They're scenarios that give each version its expected failure
profile so CI can exercise guardrails, graders and the gate with no key:

- v1 answers off-topic questions, recommends funds, repeats scraped guarantees, cites nothing, and mixes up
  similarly named funds.
- v2 mostly follows its prompt, but three answers slip (advice, guarantee, missing citation) so the output
  guardrails have something to catch. It still mixes up similarly named funds.
- v3 is correct.

Offline run summary:

```text
v2: 41 traces | refused 7 | cited 34 | guardrail edits 14
v3: 41 traces | refused 7 | cited 34 | guardrail edits 7
```
